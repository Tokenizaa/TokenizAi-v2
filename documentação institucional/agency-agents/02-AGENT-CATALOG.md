## 2. Formato do Arquivo de Agente

Cada agente é um arquivo `.md` com **frontmatter YAML** obrigatório:

```markdown
---
name: Frontend Developer                    # Nome exibido (obrigatório)
description: Expert frontend developer...   # Descrição curta (obrigatório)
color: cyan                                 # Cor nomeada (para OpenCode, etc.)
emoji: 🖥️                                   # Emoji identificador
vibe: Builds responsive, accessible...      # Tagline curta
# tools: Read, Write, Edit, Bash...        # Opcional: lista de ferramentas Claude Code
---
```

**Corpo:** Markdown livre com seções padronizadas:
- `## 🧠 Your Identity & Memory`
- `## 🎯 Your Core Mission`
- `## 🚨 Critical Rules You Must Follow`
- `## 📋 Your Technical Deliverables`
- `## 🔄 Your Workflow Process`
- `## 📋 Your Deliverable Template`
- `## 💭 Your Communication Style`
- `## 🔄 Learning & Memory`
- `## 🎯 Your Success Metrics`
- `## 🚀 Advanced Capabilities`
- `---` + **Instructions Reference** (aponta para arquivo externo opcional)

## 4. Análise de Qualidade e Consistência

### 4.1 Frontmatter Coverage
- **100%** têm `name` e `description` (obrigatórios para indexing)
- **~95%** têm `color` (usado por OpenCode, renderers skill-md)
- **~90%** têm `emoji` e `vibe` (usados por OpenClaw IDENTITY.md)
- **~15%** declaram `tools` (lista Claude Code tools para Qwen/ZCode mapping)

### 4.2 Estrutura do Corpo
- Todos seguem o template de seções padrão (10-12 seções)
- Variação: alguns têm `Instructions Reference` apontando para `ai/agents/dev.md` etc. (arquivos que não existem no baseline)
- Seções `Learning & Memory` e `Success Metrics` são consistentes

### 4.3 Duplicidades e Overlaps
| Par | Divisão A | Divisão B | Overlap |

| `customer-service` vs `healthcare-customer-service` | specialized | healthcare | Domínio similar, contextos diferentes |

| `project-manager-senior` vs `studio-producer` | project-management | specialized | Escopo diferente (projeto vs portfolio) |
